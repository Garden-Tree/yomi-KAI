# 公開版（ホスティング）の運用

yomi-KAI を自分のサーバーだけでなく、不特定多数のサーバーに招待してもらう「公開版」として動かすときの推奨設定と運用手順です。
ここで紹介する設定はすべて任意で、書かなければ自分のサーバー向け（セルフホスト）と同じ動作になります。

## 1. 推奨設定（config.ini）

`config.ini` の `[DEFAULT]` に、必須項目（`DISCORD_TOKEN` など）に加えて次を書きます。

```ini
; 読み上げた本文をログに残さない（既定と同じ。明示しておく）
LOG_READ_TEXT = False
; 1メッセージで読み上げる最大文字数
MAX_READ_LENGTH = 100
; サーバーごとの辞書の登録数の上限
MAX_DICT_ENTRIES = 200
; 個人辞書（y.mydict）の1人あたりの登録数の上限
MAX_USER_DICT_ENTRIES = 10
; 使える話者（0.vvm の4キャラクターのノーマルスタイル）
SPEAKER_ALLOWLIST = ずんだもん, 春日部つむぎ, 四国めたん, 雨晴はう
; Discord から長時間切断されたときの通知先
ALERT_WEBHOOK_URL = https://discord.com/api/webhooks/xxxx/yyyy
; 同時に音声合成する数（下記の目安を参照）
VOICEVOX_WORKERS = 2
; 月ごとの使用量を記録する
RECORD_USAGE = True
; 読み上げと関係ない「突然の死」コマンド（y.sd・/sd）を外す
ENABLE_SUDDEN_DEATH = False
```

* **`LOG_READ_TEXT`**: `False`（既定）のとき、メッセージの本文はログに一切残りません。yomi-KAI 自身のログは文字数だけを記録し、本文を含む discord.py の詳細ログ（受信したイベント・送信したリクエストの中身）も出力しません。不具合の調査で一時的に本文を見たいときだけ `True` にし、終わったら戻してください。
* **`MAX_READ_LENGTH`**: 長文の連投で合成が詰まらないよう、100 文字程度を推奨します（超えた分は「以下略」）。
* **`MAX_DICT_ENTRIES`**（既定 0 = 無制限）: 辞書ファイルが際限なく大きくならないようにします。上限に達したサーバーでは新しい単語を登録できません（登録済みの単語の読みの変更・削除はできます）。
* **`MAX_USER_DICT_ENTRIES`**（既定 0 = 無制限）: 個人辞書（`y.mydict`）の1人あたりの登録数の上限です。考え方は `MAX_DICT_ENTRIES` と同じで、公開版では 10 程度を推奨します。
* **`SPEAKER_ALLOWLIST`**（既定は空 = すべての話者）: `y.voice list` に表示される名前をカンマ（`,` `、` `，` のいずれでも可）区切りで書きます。ここにない話者はドロップダウン・`y.voice`・`y.credit` に表示されず、保存済みの設定が許可されていない話者を指していても、サーバーの話者 → 既定の話者の順に代わりの話者で読み上げます。見つからない名前があると起動時に警告し、1つも見つからなければ起動しません。
  * キャラクター名（例: `ずんだもん`）はノーマルスタイルだけを指します。ほかのスタイルは `ずんだもん（あまあま）` のように、`y.voice list` に表示される「名前（スタイル）」で1つずつ書きます（括弧の全角・半角は区別しません）。
  * 既定で読み込む `0.vvm` には、ずんだもん・四国めたんの「ノーマル・あまあま・ツンツン・セクシー」と、春日部つむぎ・雨晴はうの「ノーマル」が入っています。同じ `.vvm` のスタイルは追加のモデルを読み込まずに使えるので、許可してもメモリは増えません。たとえば次のように書くと 10 件（`0.vvm` の全スタイル）を使えます。

    ```ini
    SPEAKER_ALLOWLIST = ずんだもん, ずんだもん（あまあま）, ずんだもん（ツンツン）, ずんだもん（セクシー）, 春日部つむぎ, 四国めたん, 四国めたん（あまあま）, 四国めたん（ツンツン）, 四国めたん（セクシー）, 雨晴はう
    ```

  * ささやき・ヒソヒソ（`5.vvm`）、ヘロヘロ・なみだめ（`15.vvm`）などは別の `.vvm` に入っており、`VOICEVOX_LOAD_ALL_MODELS = True`（すべてのモデルを読み込む）にしないと使えません。モデルは合成ワーカーごとに読み込まれるため、メモリが大きく増えます。
* **`ALERT_WEBHOOK_URL`**: 公開版では止まっていることに気付けるよう設定を推奨します（README の「切断通知」参照）。
* **`VOICEVOX_WORKERS`**: 同時に読み上げるサーバーが多いほど効果があります。メモリの目安は 1 で約 280MB、2 で約 530MB、4 で約 890MB です（README の「音声合成の同時実行数」参照）。まず 2 で始め、`docker stats` のメモリ使用量と、混雑時の読み上げの遅れを見て調整してください。CPU のコア数より大きくしても速くはなりません。
* **`RECORD_USAGE`**（既定 False）: `True` にすると、月ごとの使用量を記録します（下記「3. 使用量の確認」参照）。
* **`STATUS_PUSH_URL` / `STATUS_PUSH_TOKEN`**（既定は空 = 送らない）: 公開のステータスページに稼働状況を送ります（下記「5. ステータスページ」参照）。
* **`ENABLE_SUDDEN_DEATH`**（既定 True）: `False` にすると「突然の死」コマンド（`y.sd`・`/sd`）を登録せず、`y.help` にも表示しません。読み上げと関係ない機能を省いて、コマンドの一覧を読み上げ用のものだけにしたい公開版向けです。`False` のときは `SD_MSG` を省略できます。`y.credit` はこの設定にかかわらず使えます。スラッシュコマンドの一覧から `/sd` が消えるまでには、再起動後しばらくかかることがあります。

### プラン（フリー / プレミアム）と上限

上の `MAX_READ_LENGTH` / `MAX_DICT_ENTRIES` / `MAX_USER_DICT_ENTRIES` / `SPEAKER_ALLOWLIST` は、すべてのサーバーに適用される「フリー」の上限です。`PREMIUM_ENABLED = True` にすると、運営者が指定したサーバーだけ「プレミアム」の上限（`PREMIUM_*`）を使います。プレミアムにするサーバーは運営者が手で登録するか、サイトで受け付けた Stripe の契約を同期します（下記「Stripe の契約の同期」）。

```ini
PREMIUM_ENABLED = True
; プレミアムのサーバーの上限（空または 0 で無制限）
PREMIUM_MAX_READ_LENGTH = 300
PREMIUM_MAX_DICT_ENTRIES = 1000
PREMIUM_MAX_USER_DICT_ENTRIES = 50
; プレミアムで使える話者（空なら読み込んだすべての話者）
PREMIUM_SPEAKER_ALLOWLIST =
; プレミアムのサーバーの一覧（既定 settings/premium.json）
;PREMIUM_GUILDS_FILE = settings/premium.json
```

`settings/premium.json` には、サーバー ID と期限（その日まで有効、`null` なら期限なし）を書きます。`{"expires": ..., "note": ...}` の形にするとメモも残せます。

```json
{
  "123456789012345678": null,
  "234567890123456789": "2026-12-31",
  "345678901234567890": {"expires": "2027-01-31", "note": "1月分"}
}
```

* 保存すれば30秒以内に反映されます（Bot の再起動は不要）。期限を過ぎたサーバー・一覧から消したサーバーは、次の発言・コマンドからフリーの上限に戻ります。
* ファイルが壊れている（JSON として読めない）場合は警告をログに出し、直前に読めた内容のまま動きます。ID・日付として読めない項目だけは警告して無視します。
* `PREMIUM_SPEAKER_ALLOWLIST` を空にすると、読み込んだすべての話者（`VOICEVOX_LOAD_ALL_MODELS` などで決まる）がプレミアムで使えます。フリーの話者を絞るには `SPEAKER_ALLOWLIST` を使います。
* プレミアムから外れたサーバーで、プレミアムだけの話者を選んでいた人は、サーバーの話者 → 既定の話者の順に代わりの話者で読み上げます。辞書の登録は消えません（上限を超えた分は、上限を下回るまで新しく登録できないだけです）。
* `y.plan` で、各サーバーの利用者が自分のサーバーのプランと上限を確認できます。`PREMIUM_ENABLED = False`（既定）のときは、プレミアムについては何も表示しません。
* 将来の有料プランでは、話者の追加・複数のボイスチャンネル・優先的な合成なども想定しています（このバージョンでは上記の上限のみ）。

### Stripe の契約の同期（公開版の運営者向け・準備中）

公開版では、プレミアムの申し込みと支払いを Stripe で受け付けます。Bot はインターネットから届かない自宅のサーバーで動いているので、Stripe とのやりとり（Checkout・Webhook・Billing Portal）はすべてサイト（yomi-kai-site の Cloudflare Pages Functions と D1）が行い、Bot はサイトから契約中のサーバーの一覧を取りに行くだけです。Stripe のキーは Bot には置きません。

```
y.plan（管理者にだけ署名付きリンク）→ サイトの /premium/?t=<トークン> → Stripe Checkout（申し込み）/ Billing Portal（契約の管理）
Stripe ──Webhook──▶ サイト（POST /api/stripe-webhook）──▶ D1（subscriptions）
Bot ──5分ごとに GET /api/premium-guilds（Bearer トークン）──▶ サイト ──▶ settings/premium.json に反映
```

サイト側の設定（Stripe のアカウント・商品と価格・Webhook・Cloudflare のシークレット）は yomi-kai-site の README の「プレミアム（Stripe）」を参照してください。Bot の `config.ini` には次を足します。

```ini
PREMIUM_ENABLED = True
; サイトから Stripe の契約を同期する（5分ごと）
PREMIUM_SYNC_URL = https://yomi-kai.gadelog.com/api/premium-guilds
PREMIUM_SYNC_TOKEN = （Cloudflare のシークレット PREMIUM_SYNC_TOKEN と同じ値）
; y.plan に申し込み・契約の管理のリンクを出す
PREMIUM_SITE_URL = https://yomi-kai.gadelog.com
PREMIUM_LINK_SECRET = （Cloudflare のシークレット PREMIUM_LINK_SECRET と同じ値）
```

* トークン・シークレットは、それぞれ別の32文字以上のランダムな文字列にします（例: `python -c "import secrets; print(secrets.token_urlsafe(32))"`）。短いと起動時にエラーになります。値はログに出しません。
* **同期**（`PREMIUM_SYNC_URL` / `PREMIUM_SYNC_TOKEN`、`PREMIUM_ENABLED = True` のときだけ）: 起動時と5分ごとに契約中のサーバーと期限を取得し、`settings/premium.json` に `{"expires": "YYYY-MM-DD", "source": "stripe", "status": "active"}` の形で書きます。期限は契約の期間の終わり（日本時間の日付。支払いが滞っている間は +3日の猶予）です。
  * 書き換えるのは `"source": "stripe"` の項目だけです。手で書いた項目（`source` が無い）はそのまま残り、同じサーバーが両方にあれば手で書いた項目を優先します。解約されたサーバーは次の同期で一覧から消えます。
  * 取得に失敗した・応答の形が正しくない・`premium.json` が壊れている場合は、ファイルを書き換えません（警告は30分に1回まで）。同期が止まっても、各項目の期限を過ぎればフリーに戻ります。
  * 書き換えは一時ファイルに書いてから差し替えるので、途中で壊れることはありません。手で編集するときは、同期と重ならないよう保存は素早く済ませてください（同期は内容が変わったときだけ書き込みます）。
* **リンク**（`PREMIUM_SITE_URL` / `PREMIUM_LINK_SECRET`、`PREMIUM_ENABLED = True` のときだけ）: `y.plan` を使った人が「サーバー管理」の権限を持っていれば、「プレミアムに申し込む / 契約を管理」のリンクを渡します。`/plan` では本人にだけ見えるメッセージ、`y.plan` では DM で送ります（チャンネルには出しません）。リンクはそのサーバー専用の署名付き（サーバー ID と期限を `PREMIUM_LINK_SECRET` で HMAC-SHA256 署名）で、1時間で切れます。サーバー ID を書き換えたリンクや、期限切れのリンクはサイトが受け付けません。
* 契約はサーバー単位です（申し込んだ人ではなく、サーバーがプレミアムになります）。

### サーバーごとの設定

次の設定はサーバーごとに、各サーバーの利用者・管理者がコマンドで切り替えます。公開版でも既定値のままで問題ありません。

| 設定 | 既定 | コマンド |
| --- | --- | --- |
| 発言者の名前の読み上げ（`read_name`） | オフ | `y.readname on\|off` |
| 混雑時の早読み（`queue_speedup`） | オン（読み上げ待ちが3件以上で1.25倍、6件以上で1.5倍、最大2.0倍） | `y.speedup on\|off` |
| Bot・Webhook の発言の読み上げ（`read_bots`） | オフ | `y.readbots on\|off`（サーバー管理の権限） |
| 読み上げない人・ロール | なし（それぞれ25件まで） | `y.ignore`（サーバー管理の権限） |
| 自動接続 | なし（5件まで） | `y.autojoin`（サーバー管理の権限） |
| URL・サーバー絵文字・コードブロック・ネタバレの読み方 | 従来どおり（「URL」・名前・「コード省略」・「ネタバレ」） | `y.read`（変更はサーバー管理の権限） |

個人の設定（話者・速度・声の高さ `y.pitch`・個人辞書 `y.mydict`）はプランにかかわらず誰でも使えます（個人辞書の登録数のみ上限あり）。

**再起動後の自動再接続**: Bot は接続中のボイスチャンネルを `settings/voice_sessions.json` に記録し、デプロイや再起動のあと、そのボイスチャンネルにまだ人がいて権限があれば自動で接続し直します（再接続したことはチャンネルに投稿せず、ログにだけ残します）。`y.dc`・AFK・無人などで切断したときは記録を消すので、再接続しません。

混雑時の早読みは、多くの人が同時に発言するサーバーで読み上げが大きく遅れるのを防ぎます。`y.status` で、各サーバーから Bot 全体の接続数や音声合成の状態を確認できます（デプロイしたバージョンも表示されます）。「読み上げの開始までの時間」は、Bot がメッセージを受け取ってから再生を始めるまでの時間の中央値と95パーセンタイルです（サーバーごとに直近100件、再起動で消えます）。混雑時やワーカー数を変えたときの目安にしてください。

## 2. ブラックリスト（利用を断るサーバー）

荒らしや規約違反などで利用を断りたいサーバーは、`settings/blocked_guilds.txt`（`BLOCKED_GUILDS_FILE` で変更可。既定 `settings/blocked_guilds.txt`）に登録します。

```text
# 1行に1つサーバー ID を書く。# 以降はコメント
123456789012345678  # 2026-11 スパム
```

1. Discord の「設定 → 詳細設定 → 開発者モード」を有効にし、対象のサーバーのアイコンを右クリック →「サーバーIDをコピー」で ID を取得します（ログの `guild=...` からも分かります）。
1. ファイルに ID を追記して保存します。Bot の再起動は不要です（30秒以内に読み直します）。
1. Bot はそのサーバーで読み上げ中なら止めてから退出し、ログに WARNING でサーバー ID と名前を出します。再度招待されても、参加した直後に退出します。ブロック中のサーバーからのメッセージ・コマンド・スラッシュコマンドはすべて無視します。
1. 解除するときは、その行を消すかコメントにします（Bot は退出済みなので、改めて招待してもらう必要があります）。

ファイルが無い場合は何もブロックしません。Docker 版ではホスト側の `./settings/blocked_guilds.txt` を編集します。

## 3. 使用量の確認

Bot は、読み上げを受け付けたメッセージの文字数と件数を、サーバー・ユーザーごとに月単位で `usage/YYYY-MM.json` に記録します（`RECORD_USAGE = True` のときだけ。既定は記録しません。上限や制限はありません。本文は保存しません）。書き込みは60秒ごとと終了時にまとめて行います。月の区切りはサーバーのローカル時刻（Docker 版は日本時間）です。

集計は次のコマンドで表示できます（Bot を止める必要はありません）。

```bash
# 今月
python -m yomi_kai.usage
# 月を指定
python -m yomi_kai.usage 2026-10
# Docker 版
docker compose exec yomi-kai python -m yomi_kai.usage
```

表示されるのは、サーバー数・利用ユーザー数（重複を除く）・読み上げ文字数・読み上げメッセージ数・入退室などの読み上げ文字数と、文字数の多いサーバーの上位10件（サーバー ID・文字数・件数・ユーザー数）です。

* 文字数は「以下略」で切り詰めたあとの、実際に読み上げたテキストの長さです（辞書の置換・URL の省略などの後）。
* 入退室の読み上げ（「〇〇さんが入室しました」）はユーザーの使用量には含めず、サーバーごとの `system_chars` に数えます。
* ファイルが壊れていた場合は `YYYY-MM.json.corrupt-<日時>` に退避し、その月を数え直します（退避したファイルは上書きしません）。
* 保存先は `USAGE_DIR`（既定 `usage`）で変更できます。Docker 版ではホスト側の `./usage/` に保存されます。

## 4. 保存するデータ

公開版の Bot が保存・記録するのは次のデータです。

| データ | 場所 | 内容 |
| --- | --- | --- |
| サーバーの設定・個人設定 | `settings/{サーバーID}.json` | サーバーの話者・各種オン/オフ、読み上げないユーザー・ロールの ID、自動接続するボイスチャンネル・テキストチャンネルの ID、ユーザー ID ごとの話者・読み上げ速度・声の高さ |
| 辞書 | `dict/{サーバーID}.json` | サーバーで登録された単語と読み |
| 個人辞書 | `dict/users/{サーバーID}.json` | ユーザー ID ごとの、個人辞書の単語と読み |
| 接続中のボイスチャンネル | `settings/voice_sessions.json` | 再起動後に再接続するための、サーバー ID・ボイスチャンネル ID・テキストチャンネル ID（切断すると消える） |
| プレミアムのサーバー（`PREMIUM_ENABLED = True` の場合のみ） | `settings/premium.json` | 運営者が登録した、または Stripe の契約から同期したサーバー ID と期限（同期した項目は契約の状態も） |
| 使用量（`RECORD_USAGE = True` の場合のみ） | `usage/{YYYY-MM}.json` | サーバー ID・ユーザー ID ごとの、月ごとの読み上げ文字数とメッセージ数 |
| ブラックリスト | `settings/blocked_guilds.txt` | 運営者が登録したサーバー ID |
| ログ | `log/` | 起動・接続・コマンドの実行などの動作記録（サーバー ID、ユーザー名、チャンネル名、辞書に登録・削除した単語などを含む）。最新50ファイルを保持 |

* **メッセージの本文は保存しません。** 読み上げのためにメモリ上で音声に変換し、再生後に破棄します。音声ファイルも作りません。ログにも残りません（`LOG_READ_TEXT = True` にした場合のみ、本文がログファイルに記録されます）。
* 音声の合成はすべて Bot の動作しているサーバー上の VOICEVOX で行い、外部に送信しません。ただし `USE_GOOGLE_TTS = True` にして Google の話者を使う場合は、その話者で読み上げるテキストが Google Cloud Text-to-Speech に送信されます。
* 設定・辞書は、ユーザーやサーバーの管理者がコマンドで変更・解除できます（`y.voice reset`、`y.speed reset`、`y.pitch reset`、`y.dict del`、`y.mydict del` など）。

## 5. ステータスページ（稼働状況の送信）

利用者が「Bot が動いているか」「どのくらい安定しているか」を確かめられるよう、公式サイト（yomi-kai-site）のステータスページ（`/status/`）に稼働状況を表示できます。Bot は次の設定があるときだけ、Discord に接続している間、5分ごとに稼働状況をサイトへ送ります。

```ini
; 送り先（公式サイトの /api/heartbeat）
STATUS_PUSH_URL = https://<サイトのドメイン>/api/heartbeat
; サイト側（Cloudflare Pages のシークレット STATUS_PUSH_TOKEN）と同じ値
STATUS_PUSH_TOKEN = <ランダムな長い文字列>
; 送る間隔（秒、60以上、既定 300）。サイト側の稼働率は5分単位で数えるので、変えないことを推奨します
; （300 より大きくすると、動いていても稼働率が低く表示されます）
;STATUS_PUSH_INTERVAL = 300
```

* `STATUS_PUSH_URL` と `STATUS_PUSH_TOKEN` は両方とも指定します（片方だけ、または `https://` 以外の URL だと起動しません）。どちらも空・未設定なら何も送りません。
* トークンは `python -c "import secrets; print(secrets.token_urlsafe(32))"` などで作ったランダムな文字列にし、サイト側のシークレットと同じ値にします。`config.ini` 以外（リポジトリ・チャットなど）に貼らないでください。
* 送る内容は、Bot のバージョン（`y.status` に表示されるもの）・送信時刻・読み上げの開始までの時間（全サーバーの直近の記録の中央値・95パーセンタイル・件数、ミリ秒）・ボイスチャンネルの接続数だけです。メッセージの本文・サーバー ID・ユーザー ID などは送りません。
* 送る時刻は、5分ごとの区間の中ほど（毎時 2分30秒・7分30秒…）にそろえます。起動・復帰した直後は、そろえずにすぐ送ります。
* Discord から切断されている間は送りません。サイト側は最後の受信から約12分届かなければ「停止中」と表示し、5分ごとの受信の有無から稼働率（24時間・7日・28日）を計算します。
* 送信に失敗しても読み上げには影響しません（タイムアウト10秒、再送はせず次の回を待ちます）。失敗はログに WARNING で記録しますが、同じ警告は30分に1回までです。
* サイト側の準備（Cloudflare の D1 データベースとシークレットの設定）は yomi-kai-site の README を参照してください。
